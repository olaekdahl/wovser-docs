## Step-by-Step Approach

<Steps>
  <Step title="Read the Problem Carefully">
    Before writing any code:
    - Read the entire problem statement
    - Understand the inputs and expected outputs
    - Note any constraints (time, memory, input size)
    - Study the examples provided
  </Step>
  
  <Step title="Understand the Examples">
    For each example:
    - Trace through the input manually
    - Verify you understand why the output is correct
    - Think about edge cases not in examples
  </Step>
  
  <Step title="Plan Your Approach">
    Before coding:
    - Think about the algorithm
    - Consider time/space complexity
    - Identify potential edge cases
    - Write pseudocode if helpful
  </Step>
  
  <Step title="Write Your Solution">
    Start coding:
    - Use the starter code provided
    - Write clean, readable code
    - Add comments for complex logic
    - Handle edge cases
  </Step>
  
  <Step title="Test Locally">
    Before submitting:
    - Run against visible test cases
    - Add your own test cases
    - Test edge cases
    - Check for off-by-one errors
  </Step>
  
  <Step title="Submit">
    When confident:
    - Click Submit
    - Wait for all tests to run
    - Review results
  </Step>
</Steps>

## Common Patterns

### Arrays & Strings

```python
# Two pointer technique
def two_sum(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        current = nums[left] + nums[right]
        if current == target:
            return [left, right]
        elif current < target:
            left += 1
        else:
            right -= 1
```

### Hash Maps

```python
# Fast lookup
def find_duplicate(nums):
    seen = set()
    for num in nums:
        if num in seen:
            return num
        seen.add(num)
```

### Recursion

```python
# With memoization
def fibonacci(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fibonacci(n-1) + fibonacci(n-2)
    return memo[n]
```

## Debugging Tips

### Use Print Statements

```python
def solution(nums):
    print(f"Input: {nums}")  # Debug
    
    result = process(nums)
    print(f"After process: {result}")  # Debug
    
    return result
```

### Test Edge Cases

- Empty input: `[]`, `""`
- Single element: `[1]`, `"a"`
- All same: `[5, 5, 5, 5]`
- Negative numbers: `[-1, -2, 3]`
- Very large input (if time permits)

### Common Errors

<AccordionGroup>
  <Accordion title="Index out of bounds">
    - Check loop conditions: `< len(arr)` not `<= len(arr)`
    - Verify array access before using indices
    - Handle empty arrays
  </Accordion>
  
  <Accordion title="Off-by-one errors">
    - Be careful with `range()` end values
    - Check inclusive vs exclusive bounds
    - Verify loop starts at 0 or 1
  </Accordion>
  
  <Accordion title="Type errors">
    - Check return type matches expected
    - Convert types explicitly when needed
    - Watch for integer vs float division
  </Accordion>
  
  <Accordion title="Timeout">
    - Analyze time complexity
    - Look for nested loops to optimize
    - Consider using hash maps for O(1) lookup
    - Avoid unnecessary operations in loops
  </Accordion>
</AccordionGroup>

## Before Submitting

Final checklist:

- [ ] All visible tests pass
- [ ] Handled edge cases
- [ ] Code is clean and readable
- [ ] Removed debug print statements
- [ ] Function returns correct type
- [ ] No hardcoded test case answers

## What Happens After Submit

1. **Execution**: Your code runs against all test cases (visible and hidden)
2. **Scoring**: Points awarded per passing test
3. **Review**: AI may provide feedback on code quality
4. **Results**: Score displayed (or sent to host)

<Info>
Hidden test cases ensure you can't hardcode answers for visible tests only.
</Info>

## If You Get Stuck

1. **Re-read the problem** - You might have missed something
2. **Look at examples again** - Trace through manually
3. **Start simple** - Solve for basic case first, then generalize
4. **Take a breath** - Short mental break can help
5. **Move on** - Come back if time permits

<Warning>
Don't spend all your time on one challenge if there are multiple. Get partial credit where you can.
</Warning>
