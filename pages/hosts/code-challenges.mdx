## Execution Environments

Wovser.AI provides **four execution technologies** optimized for different use cases. Many languages support **multiple execution modes**, giving you flexibility to choose between browser-based instant execution or cloud containers with full custom control.

<Callout type="info">
  **Browser-based execution** (<WasmBadge />, <WebContainerBadge />, <SandpackBadge />) runs code directly in the participant's browser—no cloud infrastructure needed. This means **instant execution**, **zero infrastructure costs**, and **unlimited concurrency**.
</Callout>

<Callout type="default">
  **Cloud execution** (<CloudBadge />) runs code in isolated Kubernetes containers, providing **complete custom control** over the runtime environment, including custom runtimes, system packages, and advanced configurations.
</Callout>

### Runtime Environment Comparison

| Environment | Best For | Execution Location | Cost | Customization |
|-------------|----------|-------------------|------|---------------|
| <WasmBadge /> WASM | Algorithms, single-file challenges | Browser | Free | Language-specific |
| <WebContainerBadge /> WebContainer | Full-stack web frameworks | Browser | Free | npm packages |
| <SandpackBadge /> Sandpack | HTML/CSS/JS fundamentals | Browser | Free | Basic web only |
| <CloudBadge /> Cloud | System languages, custom runtimes | Kubernetes | Per-use | **Full container control** |

### <WasmBadge /> WASM Runtimes (Single-File Challenges)

Best for algorithm challenges and single-file coding exercises. Code runs **instantly in the browser** via WebAssembly.

| Language | Runtime | Features | Environment |
|----------|---------|----------|-------------|
| Python | Pyodide (CPython to WASM) | Full Python 3.11 with pytest | <WasmBadge /> <CloudBadge /> |
| JavaScript | Browser Sandbox | ES2023 support, native execution | <WasmBadge /> <CloudBadge /> |
| TypeScript | esbuild-wasm transpilation | Full TS 5.x, type checking | <WasmBadge /> <CloudBadge /> |
| Ruby | ruby.wasm | Ruby 3.2 | <WasmBadge /> <CloudBadge /> |
| Lua | Wasmoon | Lua 5.4 | <WasmBadge /> <CloudBadge /> |

<Callout type="info">
  All WASM languages **also support Cloud execution**. Choose WASM for instant, zero-cost execution, or Cloud when you need custom packages or full system access.
</Callout>

Best for framework-based projects with multiple files and npm packages. Uses **StackBlitz WebContainers** to run a full Node.js environment in the browser.

| Framework | Template | Features | Environment |
|-----------|----------|----------|-------------|
| React | Vite + TypeScript | Hot reload, npm packages, Vitest | <WebContainerBadge /> <CloudBadge /> |
| Vue | Vite + TypeScript | Composition API, SFCs, Vitest | <WebContainerBadge /> <CloudBadge /> |
| Angular | Angular CLI | Full CLI, RxJS, testing | <WebContainerBadge /> <CloudBadge /> |
| Svelte | SvelteKit | Compiled framework, routing | <WebContainerBadge /> <CloudBadge /> |

**WebContainer Features:**
- Full Node.js runtime in browser
- npm package installation
- File system operations
- Dev server with hot reload
- Test execution (Vitest, Jest)

<Callout type="info">
  All web frameworks **also support Cloud execution**. Choose WebContainer for instant browser-based preview, or Cloud when you need specific Node versions, native modules, or custom server configurations.
</Callout>

### <CloudBadge /> Cloud Execution (Full Container Control)

For languages requiring **full container environments** or when you need **complete custom control** over the runtime. Code runs in isolated Kubernetes pods with configurable resources.

| Language | Version | Features | Environment |
|----------|---------|----------|-------------|
| Java | 17+ | Full JDK, Maven/Gradle | <CloudBadge /> only |
| Go | 1.21+ | Full Go toolchain, modules | <CloudBadge /> only |
| Rust | Latest stable | Cargo, crates.io | <CloudBadge /> only |
| C++ | GCC 12+ | Full compiler toolchain, CMake | <CloudBadge /> only |
| C# | .NET 8 | Full .NET SDK, NuGet | <CloudBadge /> only |
| Swift | 5.9+ | Full Swift toolchain | <CloudBadge /> only |
| PHP | 8.2+ | Composer, extensions | <CloudBadge /> only |
| Shell/Bash | 5.x | DevOps, automation scripts | <CloudBadge /> only |
| PowerShell | 7.x | Windows automation, scripting | <CloudBadge /> only |
| SQL | SQLite/PostgreSQL | Database queries, data manipulation | <CloudBadge /> only |

<Callout type="warning">
  **Why Cloud-only?** Languages like Java, Go, Rust, and C++ require full compilation toolchains, system libraries, and complex runtimes that cannot run in browser-based WASM environments. Cloud containers provide the complete development environment needed.
</Callout>

**Cloud Execution Benefits:**
- **Custom runtimes**: Specify exact language versions
- **System packages**: Install any Linux packages needed
- **Native modules**: Full support for compiled dependencies
- **Resource control**: Configure CPU, memory, and timeout limits
- **Isolation**: Each execution runs in a fresh, isolated container
- **Real terminal**: Full terminal access for debugging

## Choosing the Right Environment

### When to use <WasmBadge /> WASM
- ✅ Algorithm and data structure challenges
- ✅ Single-file coding exercises
- ✅ Quick assessments requiring instant feedback
- ✅ High-concurrency scenarios (unlimited parallel executions)
- ✅ Cost-sensitive deployments

### When to use <WebContainerBadge /> WebContainer
- ✅ React, Vue, Angular, Svelte projects
- ✅ Multi-file web applications
- ✅ npm package usage (React Query, Axios, etc.)
- ✅ Live preview during development
- ✅ Frontend framework interviews

### When to use <SandpackBadge /> Sandpack
- ✅ HTML/CSS fundamentals
- ✅ DOM manipulation exercises
- ✅ Basic JavaScript challenges
- ✅ Web design assessments

### When to use <CloudBadge /> Cloud
- ✅ System programming languages (Java, Go, Rust, C++)
- ✅ Custom runtime versions or configurations
- ✅ Native dependencies or system packages
- ✅ Full terminal access requirements
- ✅ Backend/API development challenges
- ✅ Database connectivity (SQL challenges)

## Creating a Code Challenge

<Steps>

### Define the Challenge

Provide clear context:
- **Title** - Descriptive challenge name
- **Description** - Problem statement and requirements
- **Difficulty** - Easy, Medium, Hard
- **Time Limit** - Suggested completion time

### Write the Problem Statement

Include:
- **Context** - Why this problem matters
- **Requirements** - What the solution must do
- **Constraints** - Limits and edge cases
- **Examples** - Input/output samples

### Set Up the Workspace

Configure the coding environment:
- Select supported language(s) and execution environment
- Choose <WasmBadge /> for browser execution or <CloudBadge /> for container control
- Provide starter code (optional)
- Include helper files if needed
- Configure terminal access

### Create Test Cases

<Tabs items={['Visible Tests', 'Hidden Tests']}>
  <Tabs.Tab>
    Visible test cases help participants understand the requirements. Include:
    - Basic functionality tests
    - Edge case examples
    - Sample inputs from the problem statement
  </Tabs.Tab>
  <Tabs.Tab>
    Hidden test cases validate the solution thoroughly:
    - Edge cases not revealed to participants
    - Performance tests (large inputs)
    - Security tests (input validation)
  </Tabs.Tab>
</Tabs>

### Configure Scoring

Set how submissions are evaluated:
- **Pass/Fail** - All tests must pass
- **Partial Credit** - Points per passing test
- **Code Quality** - Style and best practices
- **Performance** - Efficiency metrics

</Steps>

## Workspace Features

### Real Terminal Access

## Best Practices

### Writing Good Problem Statements

1. **Be specific** - Clearly define inputs, outputs, and constraints
2. **Include examples** - Show expected behavior
3. **Mention edge cases** - Help participants understand boundaries
4. **Keep it focused** - Test one concept at a time

### Creating Effective Test Cases

- Cover happy path scenarios
- Include boundary conditions
- Test error handling
- Consider performance implications
- Balance visible vs hidden tests
